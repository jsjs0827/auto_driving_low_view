# RGBD 与视差接入

`r33_stereo_inputs` 复用保留的 `demo_camera::Source`，通过真正的
`libMoGeneralSDK.so` 取得 RGBD 数据。相机适配器使用原始 RGBD 左目
640×544 NV12 和 SDK 连续视差模式 2；SDK 内部执行立体视差算法及其 BPU
分支。本模块仅校验、持有、提供数据，不实现或替代视差网络，也不修改 SDK
的取帧比例、相机配置文件或二进制。

外部程序可以直接提供同步的左图与 uint16 Q8.8 视差；`validateDisparity`
要求相同的帧号、非零时间戳和分辨率，校验行跨度、缓冲区大小与内参。
帧号零有效；时间戳零不能证明同步，因此拒绝。`copyDisparity` 逐行复制有效
像素到独立的紧凑缓冲区，支持带行补齐及非对齐地址。原始 Q8.8 数值保持不变。
内参的 `bxf` 保留原项目毫米单位，不能直接当作米单位基线使用。
元数据一致仅证明 SDK 标识一致，不额外证明传感器曝光的物理同步。SDK 时间戳
原样传递，适配器不会推测单位、重新编号或通过除以三来改写帧号。

相机适配器启用原 Source 的 RGBD 元数据审计和视差复制。SDK 如果没有交付完整
的同帧元数据，将返回错误；不会用空图、旧帧或模拟算法替代。原 Source 只复制
左图和视差，右图仅保留经过校验的帧号、时间戳、尺寸和字节数，
`right.pixels_available` 始终为 false。

`CameraAdapter::next()` 同步取一帧，返回的左图、视差独立于 SDK 帧释放和后续
取帧。`close()` 幂等，并暴露 SDK 关闭、模式恢复或动态库关闭失败的原始错误码。
调用方不能把关闭/销毁与其他方法并发调用。生产使用一个相机 Source；测试的
注入 Source 仅验证接口合约，不代表 X5 相机或 BPU 已实测。

本模块不依赖受保护的 `base_framework` 或 ROS 共享内存声明。相机二进制 SDK、
传感器驱动、GDC 文件、BPU 运行库及对应配置仍需在 X5 上提供。已有相机节点
持有设备时，应由该节点向完整 SO 提供左图与视差，避免再次打开相机。

## 原流程的 GDC 高分辨率输入

原始回充 `host.use_hires=true` 使用 1280×1088 GDC 左图。点云着色配置虽然包含
`pointcloud_color.use_gdc_image`，原始实际调用链仍使用 RGBD 左图；不得仅根据
配置名称推断已经使用 GDC。完整回充流程由拥有相机句柄的调用程序提供 GDC，并用
`validateHires` 校验同帧帧号、时间戳、NV12 布局与尺寸。不得用低分辨率左图
替代 GDC 来声称原流程不变。

保留的 `demo_camera::Source` 不公开相机句柄。真实 SDK 的
`moGetOneGdcFrame` / `moReleaseGdcFrame` 都要求 `nHandle`，接口中没有获取当前
句柄的 API。因此仅额外 `dlopen` 不能安全获得 GDC；适配器不会猜句柄值或再次
打开同一相机。离线 demo 可读取同帧配对的高分辨率原始文件。

新增的 `FullCameraAdapter` 独立拥有一个真实相机句柄，使用厂商原始头文件的
函数类型动态加载 SDK，在同一个句柄上获取 RGBD 和 GDC。它启用 SDK 连续视差
模式 2，复制并释放每一次取得的 SDK 帧，再按相同帧号和完全相同时间戳配对。
较旧的已复制帧可丢弃以等待配对，超过超时返回错误；不会把近邻时间戳、旧视差
或低分辨率图当作同帧高分辨率输入。返回 `Frame.hires_left` / `hires_info`。
关闭时恢复原有效模式，并在相机关闭失败时保留 SDK 映射，避免卸载仍在运行的
厂商代码。

`FullCameraAdapter` 仅在 Linux/X5 并启用真实 BPU 构建时编译真实相机分支。
其他构建显式返回相机不可用错误；本机单元测试不代表实际配对行为已在 X5
验证。SDK API 若内部阻塞，适配器的重试超时无法抢占厂商函数调用。
