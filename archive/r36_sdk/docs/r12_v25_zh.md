# r12-v25：接回原 DAG／Task／Feature 框架

本修订已加入相机回调收尾兼容修复。先按 [回调收尾修复说明](r25_callback_fix_zh.md) 运行短检查，再执行下列完整 A/B。

本轮将已验证的精确缩放、直接 BPU 输入写入和 CPU 分割优化接回原框架。原 `runtime::Engine`、`TaskGraph`、`FeatureRegistry`、`ArtifactStore`、JSON DAG 解析器及内置 Feature 实现按文件散列保留。当前所有图像一致性、性能、长测、重开和按需视差测试均由这套框架执行。

检测仍对相机原始 YUV 做 letterbox；分割仍直接缩放至原模型输入，使用原兼容的完整原图尺寸 mask。原 BIN、FMA 顺序、阈值、NMS、类别、插值和 argmax 规则保持。单帧 batch=1，无双缓冲、无跨帧队列；默认仅在同一帧内并行检测和分割。此包只开放精确原模型路径。

## 具体接入位置

| Task | 注册 Feature | 执行内容 |
| --- | --- | --- |
| input | `input.exact.pack` | 原 I420/NV12 的等值紧凑打包，不改变尺寸、视野或像素值；原始参考路径直接使用原 YUV |
| detection | `ai.exact.det.preprocess` | 原 letterbox，独立 Y/U/V FMA 校准，精确 NEON 循环、缓存坐标表、静态补边复用、直接写入 BPU 输入，逐帧 cache clean |
| detection | `ai.exact.det.backend` | 原检测 BIN，提交、等待、释放任务、失效输出缓存 |
| detection | `ai.exact.det.postprocess` | 原输出解码、阈值、NMS、坐标还原及类别名 |
| segmentation | `ai.exact.seg.preprocess` | 原直接缩放；相同精确循环和直接输入写入 |
| segmentation | `ai.exact.seg.backend` | 原 PIDNet BIN，逐帧完整推理 |
| segmentation | `ai.exact.seg.postprocess` | 保留已经验证的同类区域填充及边界完整插值／argmax，输出原图尺寸 mask |
| disparity | `stereo.demand` | AI Task 成功提交结果后，按显式设定的交付帧间隔请求视差；预热不请求 |

使用 `ai.exact.*` 名称明确选择兼容的计算实现；原 `ai.preprocess`、`ai.backend`、`ai.det.postprocess`、`ai.seg.postprocess` 和融合等内置 Feature 仍保留注册。没有把完整旧 Runner 包成一个 Feature。`NativeStages` 只分阶段操作原模型与张量，没有调度线程；生产 `dag_flow_worker` 不调用旧 `inferNv12` 或 `PersistentPair`。

默认 JSON：`profiles/dag_exact.json`。结构为 `input → parallel(detection, segmentation) → disparity`。`profiles/dag_exact_serial.json` 提供框架内串行对照。相机采集发生在 `FrameInput` 生产端，采集/纯相机资源对照使用 `dag_capture.json` 的 input、disparity Task，不加载模型。

## 帧、结果和资源归属

SDK 帧号和时间戳原样传入 `FrameInput`，经打包 Packet、分支 Invocation 传递；零帧号有效。Task 内三个 Feature 顺序执行，Task 全部成功后由原 ArtifactStore 事务提交。视差依赖两个 AI Task，失败时不请求视差。最终 `FrameResult.frame`、检测、分割和视差结果属于同一次同步 `Engine::run`。

导出仅包含最终结果；借用输入、打包指针和 Invocation 不导出。分割结果通过不可变共享引用交付，保留上一帧结果不会被下一帧覆盖。下一帧在当前 DAG 完成之后才进入。原调度器使用固定工作线程，各 Feature 显式恢复调用帧的浮点环境。兼容计算的进程级工作区在整帧范围内串行保护。

FeatureRegistry 关闭钩子在调度器结束后释放模型/张量，并失效输入目的缓存，避免重新分配后复用旧补边状态。CMA 是否完全恢复仍必须以板上长测与重开证据判断。

## 验收与回传

验收要求：检测和分割 prepared NV12、实际 BPU 输入存储均零字节差；原图 mask 零像素差；检测类别和浮点坐标/置信度逐位一致。无 GT 标注时，这证明与基线一致，不等于 mAP/mIoU。

新增 `framework_summary.json` 验证所有图像阶段的 DAG 运行证据。每个阶段包含：

- `dag_profile.json`、`registered_features.json`：本次实际图配置和注册列表。
- `graph_frames.csv`：包括预热、参考与候选在内的每次 Engine 调用、原帧号、时间戳及 Task/Feature 数量。
- `dag_trace.jsonl`：验收和开启阶段计时时的逐 Feature 顺序、线程、起止时间及 Task 状态。
- `frames.csv`：测量样本通过 `dag_run_id` 精确对应 Engine 调用，补充 `dag_graph_ms`。

`wall_ms` 延续 AI 处理口径，扣除 stereo.demand Feature；`dag_graph_ms` 包含完整 DAG 和按需视差。FPS 包含等待取帧、完整 DAG 和记录；分支可重叠，六段耗时不能直接相加。详细追踪的影响由 profile on/off 对照衡量；关闭后仍记录轻量的每帧 DAG 对应行。

回传每次结果目录的 `metrics_only.tar.gz` 和 `.sha256` 即可分析性能、框架开销、CMA 与重开。失败帧的原始输入和大体积张量保留在板上，必要时再取。

本机验证只覆盖 Windows 编译、原框架契约、模拟 hbDNN 生命周期和数值回归。真实 AArch64 Linux 交叉编译、X5 零差、FPS、CPU、RSS 和 CMA 以本次板上测试为准。迁回框架本身不预先承诺提速。
