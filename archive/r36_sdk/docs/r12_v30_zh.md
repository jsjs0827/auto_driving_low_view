# r12-v30 使用说明

本版从 r29 创建，补齐原产品业务事件接入与单模型兼容。完整对照见 [原始项目对比](r30_original_comparison_zh.md)。源码包包含完整 product 源码；Windows CPU 运行包只运行独立 ONNX AI DAG，未包含可加载的完整 ROS 产品插件。

## Ubuntu 宿主机交叉编译

继续使用原来的外部脚本入口，不需要先进入 Docker，不需要新的 hb_mapper 镜像，不要 `source` 脚本。

```bash
cd /home/st/ini_code/perception-x5-business-dag-r12-v30
python3 tools/integrity.py .
sudo bash tools/build_in_container.sh \
  --container obs-v004-x5-build \
  --sysroot /work/obs_v004_x5/sysroot_docker \
  --out /home/st/ini_code/r30_product_release
```

默认构建独立精确 AI worker 和 host 可移植产品编排测试，不构建 ROS/PCL 插件。产物在 `--out`：`perception-sdk-x5-r12-v30-business-dag.tar.gz` 及同名 `.sha256`。

需要真正构建全产品时，在上述命令末尾添加以下参数。路径均为原 C++ 容器内路径，回充目录必须是与原 API 匹配的头/库组合；本机现有候选库尚不匹配。

```bash
  --product \
  --deps-root /work/obs_v004_x5/ai_ws/src \
  --recharge-root /实际匹配的回充SDK目录
```

依赖预检命令（只读）：

```bash
python3 tools/probe_product_dependencies.py --help
```

全产品目标是 `product_percep_demo`，输出 `lib/ai_node/libpercep_demo.so`，由原 daye/ROS2 ai_node launcher 加载。没有对应的真实 launcher 命令时，不应拿独立 `dag_flow_worker` 代替全产品测试。

以上为框架/契约测试，不是完整相机/ROS/PCL 验收。真实插件是否编译进 SDK，请检查 `PRODUCT_CAPABILITIES.json` 的 `full_product_plugin_compiled`。

## JSON 配置

继续用原简化配置工具：

```bash
python3 tools/product_config.py --config profiles/product_full.json --dry-run
```

模型路径、外部原配置与 `launch.argv` 必须改为实际部署路径。新离线示例为 `profiles/product_offline.json`，输入包含 `kind=offline`、`rgb_dir`、`disparity_dir`、`interactive`。它保持原几何回放，不自动运行 AI。文件按相同 stem 配对；RAW 为原 640×544 uint16 视差数据。

`product.events_profile` 可选，默认 `product/config/product_events.json`，prepare 时冻结为启动目录的 `product_events.json` 并映射到 `product.events_config`。高级事件图仍为原 config_version=3 JSON：不得漏 Feature、跨事件依赖或把保存放在参数验收之前。

每帧业务指标与回调/后台指标分别记录，后者有 event_id 和 parent_run_id。完整错误保留在 Status JSON 与 C API，不能只看 shell 退出码。

## Windows / Ubuntu x86 CPU

CPU 后端沿用 [r29 CPU 操作说明](r29_cpu_zh.md)，项目目录及产物名改为 r30。Windows 预编译包含真实 ORT DLL/许可证；需自行提供两个 ONNX 和显式输入输出契约，不含模型。CPU 的基线/优化一致性不能代替 CPU/BPU 精度一致性。

所有交付文本在打包前按最终 UTF-8/LF 字节校验，`.sha256` 为 LF。不要在解压后用 Windows 工具转换源码换行后继续使用旧校验清单。
