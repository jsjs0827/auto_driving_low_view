r12-v23：精确缩放、完整性能对比与 CMA 释放

本包接续 r22 FMA 修复 v2。检测保持原 864×480 letterbox，分割保持原图直接缩放到 832×480、原 PIDNet BIN 和完整原图 CPU 后处理。使用原始检测 BIN，单帧逐帧处理，同帧检测和分割并行，无跨帧双缓冲。

本机 Windows 已完成主机测试与 ARM NEON 类型检查。没有在本机执行 Ubuntu AArch64 交叉编译或真实 X5 推理，不预报 FPS。板端脚本必须先通过输入零字节差、mask 零像素差、检测位级相等，才开始性能测试。

本次新增优化

保留 r21、cached、direct 对照。新增 compact_cached 和 compact_direct，数学运算和最终取整顺序保持。

  • 热块表从 152 字节缩为 96 字节，将少量边缘 gather 的 16 个完整整数索引移到独立 16 位表。紧凑表中只保留热循环需要的索引、权重和类型。两套映射均留作对照，块表字节字段表示当前循环访问的表，不等于进程总 RSS。
  • 将左右邻点索引合成一个 16 字节向量，每个源行使用一次 128 位 TBL 查询。四个 64 位查询改为两个 128 位查询；查询总数据量相同，实际吞吐由 X5 实测决定。
  • 块表计数在几何初始化时预计算，避免每帧重新扫描。旧对照的取样/FMA/写入循环保持，统一更新统计方式和计时。
  • 保留补边缓存、对齐尾部置零和每帧必要 cache clean。compact_direct 直接写入已有 BPU 输入内存，不取消缓存清理。
  • 新增 Y 缩放、UV 缩放、补边、坐标表、校准、复制、cache clean、审计、尾部和统计开销计时。只在阶段边界取时间，不在每个像素或块上计时。

Y/U/V 仍分别校准实际 runner 的 FMA 顺序。原 U 像素偏移 481404 的 127 回归、独立通道模式、不同格式/步长、边界及对齐尾部测试全部保留。

完整测试：性能、10 分钟长测、同进程重开及按需视差

沿用已经确认的原模型路径。主测试的 mode=0 保留 SDK 原视差设置，不代表关闭视差。相机配置与原 SDK 不覆盖；full-sync 仍使用受校验的独立 SDK 副本。

bash tools/run_x5.sh \
  --det-model /userdata/ai_infer/data/mmyolo0828.bin \
  --seg-model /userdata/ai_infer/data/pidnet_0825_3classes.bin \
  --sdk-policy full-sync --stream gdc --format i420 \
  --disparity-mode 0 --schedule free \
  --frames 120 --warmup 20 --rounds 2 \
  --long-seconds 600 \
  --reopen-count 5 --reopen-frames 60 \
  --test-demand-every 10 \
  --verify-save-every 10 --verify-visualize-every 0 \
  --resource-interval-ms 500 --settle-seconds 5 \
  --out /userdata/r12_v23_res

程序有界运行，全部测试完成或任一验收失败后退出。不会一直采集。完整测试预计十几分钟，具体取决于板端速度和相机启动耗时。长测目标为预热后 600 秒，另有 100000 帧安全上限；提前碰到帧上限会标记未完成，不能冒充 600 秒长测。

执行次序：

  1. 原生原前处理、旧/新精确输入、原后处理、线程生命周期测试。
  2. 有界采集 10 帧原图，并冻结为固定输入。
  3. 原始标量→r21 与五条输入路径的同帧实际 BPU 零差验收。
  4. 五条路径固定回放与相机在线，分别按正序、反序各测一轮，共 20 个性能阶段。性能阶段不保存大文件和 PNG，不计算完整 mask 哈希。
  5. 被本轮选择的输入路径再测计时开关 on/off，以检查诊断计时影响。
  6. 被选择路径进行 600 秒长测。
  7. 同一工作进程保持模型打开，关闭/重开相机 5 次。每次关闭后观察 1 秒，再重开并额外预热 5 帧。
  8. 显式 mode=1 的 demand_idle（不请求）与 demand_disparity（每10帧请求），记录调用次数、均值/P95/最大延迟和返回码。

主性能对比中的输入、模型、线程策略、BPU priority=0、相机 SDK 策略与视差模式相同。相机重开阶段 FPS 包含关闭、释放等待、重开和额外预热，属于稳定性数据，不当作正常在线 FPS。

固定原图 TSV 使用真实板端路径。若旧目录已经移走，应给 --input-list 指定实际存在的 TSV，并确认其中每帧原图路径可读取，不要把 fused BIN 替换为原模型。

报告与计时口径

  • report.html：五条路径固定/在线性能、同类新旧紧凑路径对比、Y/UV/复制/cache clean 细分、CMA恢复和视差延迟。
  • report.md：全部测量阶段和本轮建议。
  • input_summary.json：各阶段均值/P95/最大值，两轮汇总与候选选择。至少两轮、严格验收通过、整帧改善至少3%并满足FPS/P95/CPU/RSS门槛才推荐新路径；推荐仍须结合长测。
  • resource_summary.json：关闭/退出的CMA恢复、预热后RSS/CMA趋势、同进程相机重开事件、按需视差延迟。CMA 为整板观测，不能单凭差值认定泄漏。
  • 阶段资源文件：外部每500ms读取板端CMA和工作进程RSS/线程/FD，覆盖模型初始化、相机打开和退出后等待。外部采样器CPU不包含在子进程CPU百分比里。
  • resource_events.jsonl：分别记录 before/after_model_init、camera_open、warmup、模型释放、相机关闭、每次相机重开及关闭后1秒观察。
  • frames.csv：新增 det/seg_pack_ms、calibration_ms、map_ms、padding_ms、y_ms、uv_ms、tail_ms、account_ms、copy_ms、clean_ms、audit_ms、block_bytes、tail_bytes，以及 camera_cycle、CmaTotal、MemAvailable、VmHWM、session_elapsed_ms。

r21 只沿用整体前处理计时，其细分 Y/UV 字段未测，不能将 0 解释为没有缩放。verify 会同时运行参考和候选并进行输入/输出审计，CPU时间与RSS不和单遍性能阶段直接比较；默认每10次保存一次成功完整证据，失败总会保存完整证据。若需所有成功原图，可设 --verify-save-every 1。

稳态验收会检查 direct/compact_direct 的 copied_bytes=0；候选稳态 padding_bytes=0、初始化计数=0；尾部仍置零。cache clean 必须保留。profile_overhead_on/off 检查计时本身的扰动，不能把开关造成的变化误算为算法收益。

输入/输出零差证明流程一致，不等于无 GT 的 mAP/mIoU。固定回放FPS与在线FPS分别评估。API等待包含模型执行与排队，只有整帧结果和受控视差对照才能说明在线收益。
