# 模块化 v2：调度层拆分、构建与验证

## 本轮范围与版本边界

v2 由已校验的 v1 独立复制，继续把原 SDK 中的主要代码移到新层次：`scheduling/` 管配置解析、DAG 构建验证、执行和具体产品编排；`features/` 放数值算法及输入输出；`core/` 放共用数据与基础设施；`sdk/` 保留公开接口、薄 C ABI、构建和安装。原 SDK 历史参考迁入 `archive/r36_sdk/`，不再作为活动实现入口。详见 [调度层设计](07_调度层设计.md)。

源文件迁移记录见 `validation/evidence/v2_source_layout.json`，复制时 v1 身份见 `PREVIOUS_VERSION_SHA256SUMS`，原 v10 身份见 `BASELINE_SHA256SUMS`。当前包完整性以根 `SHA256SUMS` 为准。本轮验证以 `validation/evidence/v2_*` 为准；下文 `modular_*` 表格是 v1 历史证据，不能当成本轮已通过。

**最重要的构建规则：先重编本项目 SDK，安装到新目录，再让应用构建和运行的 SDK_ROOT 都指向新目录。** 只重编 ROS 前端仍可连接旧 SDK，但不能验证本轮内部调度/C ABI/算法的改动。

## 交付内容

项目根目录为 `perception-stereo-modular-v2`。源码包包含按功能归档的应用 C++、真实 SDK 后端源码、根配置、功能配置、参数索引、编译/运行/比较工具和阅读文档。当前 SDK 来源索引为 `sdk/SOURCE_PROVENANCE.json`，原 v1 记录保留为 `archive/modular_v1_sdk_source_provenance.json`；本轮搬迁以 `validation/evidence/v2_source_layout.json` 为准。`BASELINE_SHA256SUMS` 是原 v10 身份记录；当前包完整性用根目录 `SHA256SUMS`。

团队分享 PPT 为 **42 页、16:9、可编辑文字和表格**，包含每页讲解备注；独立交付文件名 `双目感知系统_架构与开发分享_完整版.pptx`。这套 PPT 和逐页文字版 [05_分享讲稿.md](05_分享讲稿.md) 反映 v1，v2 的结构补充见 [07_调度层设计](07_调度层设计.md) 末尾。[06_分享备课与问答.md](06_分享备课与问答.md) 提供另一套 30 主题备课组织和问答。

模型、相机厂商 `.so`、Horizon 运行库和 ROS 发行版继续使用现有环境。源码压缩包不是已完成板端验证的生产二进制包；以下交叉编译会使用真实 AArch64 SDK/ROS 生成 X5 发布包。

## 从 v1 保留的功能分类

1. 相机、离线、ROS、Stereo、共享推理、点云、融合、指标和 SDK 调用分别归档。头文件与实现分开；真实 SDK 数值算法放在所属功能的 `backend/`。
2. 全局输入和视差选择放 `pipeline.json`，统一相机设置放 `camera.json`，统一发布和保存设置放 `visualization.json`。
3. 功能参数的 `config.json`、`adapter.py` 与 `parameter_map.json` 对应实际读取者。固定或不支持的契约明确拒绝无效修改。
4. `core/` 收纳共享数据契约与小工具；现阶段不增加无实际用途的继承基类。
5. ROS 主类的方法拆到输入、处理、输出和指标文件，原调用行为保持。类的职责仍然偏多，已作为下一步解耦方向记录。

检测与分割共用模型会话管理、输入校准和调度，数值实现保留在 `features/inference/backend/`，内层 DAG 编排移到 `scheduling/inference/`；检测的 IoU/NMS、分割的 CHW argmax，以及当前实际使用的双线性工作空间与参考实现，分别有自己的 `backend/include/`、`backend/src/`。各自参数与适配器独立，未复制两套推理引擎。应用构建与 SDK 构建分开，是动态库加载的实际边界。

## Ubuntu 交叉编译

沿用现有主机、容器、sysroot。下面 `--sdk-root` 保留原来可用的安装位置，便于前端兼容运行；要验证 v2 调度代码，必须替换为重编 v2 得到的新 AArch64 SDK 安装前缀。后面的 `tools/build_backend_sdk.sh` 说明 SDK 构建入口。

```bash
cd /home/st/ini_code
tar -xzf perception-stereo-modular-v2.tar.gz
cd perception-stereo-modular-v2

python3 tools/verify_files.py .

bash tools/build_in_container.sh \
  --container obs-v004-x5-build \
  --sysroot /work/obs_v004_x5/sysroot_docker \
  --sdk-root /tmp/r12-v36-20261008-215622-3654808/install/perception_full_shared_sdk \
  --stereo-horizon-root /work/obs_v004_x5/sysroot_docker/usr_x5 \
  --out /home/st/ini_code/perception_stereo_modular_v2_release
```

该命令构建算法节点、相机发布节点、新 Stereo runner、录制与对比程序，并打包为 `perception-stereo-modular-v2-x5`。依赖缺失、架构不匹配时停止，不使用替代库。具体输出路径以脚本打印为准。

如果修改了后端算法，先构建新 SDK，再将上面 `--sdk-root` 和运行时的 `SDK_ROOT` 都替换成新 SDK：

```bash
# CPU / x86：需要真实 ONNX Runtime C++ SDK、PCL、Eigen、OpenCV 等
bash tools/build_backend_sdk.sh \
  --backend cpu --ort-root /path/to/onnxruntime \
  --build-dir build/backend_cpu --install-dir install/backend_cpu

# BPU / AArch64：在现有容器中执行，使用已有交叉工具链及真实 ARM 依赖
bash tools/build_backend_sdk.sh \
  --backend bpu \
  --horizon-root /work/obs_v004_x5/sysroot_docker/usr_x5 \
  --toolchain "$PWD/sdk/cmake/x5-toolchain.cmake" \
  --build-dir build/backend_x5 --install-dir install/backend_x5 \
  -- -DX5_SYSROOT=/work/obs_v004_x5/sysroot_docker \
     -DCMAKE_PREFIX_PATH=/path/to/target/dependencies
```

最后两条中的 `/path/to/...` 是需要按环境填入的依赖位置，不是已经存在的目录。默认关闭 recharge 后端，保留检测、分割、点云融合所需组件。修改 SDK 后不要继续运行旧 `SDK_ROOT`。

## Ubuntu / WSL 的 x86 应用编译

Windows 使用现有 WSL Ubuntu，在 Linux 终端中执行。需要已安装的同架构 CPU full SDK、ROS 2 Humble、CMake、Ninja、OpenCV 及 SDK 的真实运行依赖。`build_native.sh` 通过环境变量接收设置，不接受交叉编译脚本的 `--sdk-root` 等参数：

```bash
cd /absolute/path/to/perception-stereo-modular-v2
export SDK_ROOT=/absolute/path/to/native/perception_full_shared_sdk
export ROS_SETUP=/opt/ros/humble/setup.bash
export NATIVE_BUILD_DIR="$PWD/build/native"
export INSTALL_ROOT="$PWD/install/perception_ros_so_demo"
export BUILD_JOBS=4
bash tools/build_native.sh
```

`SDK_ROOT` 必须含 `lib/cmake/perception_full_shared_sdk/`，不能指向 AArch64 SDK。该脚本配置、编译、运行已注册 CTest 并安装。默认不构建 Horizon runner；只有环境中已经有匹配的 x86 Horizon 头文件和运行库时，才额外设置 `STEREO_HORIZON_ROOT`。编译了 runner 也不表示可以在普通 x86 CPU 上执行 X5 BIN。

CPU 运行需要 SDK 的有效配置选择 `inference.backend="cpu"`，引用真实 `cpu_profile` 和对应 ONNX 模型；原 Q8.8 方法可用已录制数据或 ROS 输入进行回归。调用 `python3 tools/run_pipeline.py ...` 或录制入口 `python3 compare/run_compare.py ...`；`tools/run_pipeline.sh`、`run_camera_x5.sh` 为 X5 环境入口。若把 `INSTALL_ROOT` 改成其他位置，还需在主配置的 `runtime.executable` 或 `recording.runner` 中填写对应程序路径。录制准备需要现有 Python NumPy/OpenCV，在线配置前端只使用 Python 标准库。

统一录制入口为 `tools/capture_stereo.py`，X5 可调用同名 `.sh`。采集、ROS 相机发布和录制都读取主配置引用的根 `camera.json`。录制相机 SDK/配置路径的优先级为命令行参数 > `CAMERA_SDK` / `CAMERA_CONFIG` 环境变量 > `camera.json`，超时读取 `acquire_timeout_ms`。为了同时录制左右图与原 Q8.8，录制程序固定使用 `mode=2`、`need_q8=true`，重试间隔为 `min(5, timeout)`；这里不套用 JSON 的 `disparity_mode`、`retry_interval_ms` 或 ROS `frame_id`。

## X5 相机直取

```bash
cd /userdata
tar -xzf perception-stereo-modular-v2-x5.tar.gz
cd perception-stereo-modular-v2-x5

export SDK_ROOT=/userdata/ai_infer_r12_v36/perception-core-x5-r12-v36/install/perception_full_shared_sdk
export DET_MODEL=/userdata/ai_infer/data/mmyolo0828.bin
export SEG_MODEL=/userdata/ai_infer/data/pidnet_0825_3classes.bin
export STEREO_MODEL=/userdata/stereo_pro/r34_tail_pointwise_shuffle2_grouped_grid_352x640_nv12_mixed.bin
export LD_LIBRARY_PATH="$SDK_ROOT/lib:/app/deps:/usr/hobot/lib:${LD_LIBRARY_PATH:-}"

bash tools/run_pipeline.sh \
  --run-dir /userdata/stereo_results/modular_$(date +%Y%m%d_%H%M%S)
```

默认根配置为 `camera` + `raft_stereo`；相机路径在根 `camera.json`。新模型按 NCHW `[1,3,352,640]`、NV12 图像契约处理。`run_pipeline.sh` 负责查找/source ROS 与应用安装环境，在线入口使用系统 Python 3 标准库，不需要另建虚拟环境。

上面的 `SDK_ROOT` 是原 SDK 部署位置。若本次测试对象是 v2 的调度/C ABI 后端，把新 SDK 安装传到板端，并将该变量改为新安装前缀，核对实际加载 `.so` 的路径和哈希；否则只能说明新前端兼容旧后端。

运行目录保存本次有效配置和 `metrics.jsonl`。要保存每帧结果/PLY，修改根 `visualization.json` 的 `save_root` 为非空目录；严格内容回归将 `save_every_n` 设为 1。ROS 模式、离线模式、话题检查及停止方法见 [新手阅读与开发](03_新手阅读与开发.md)。
