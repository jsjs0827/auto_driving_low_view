# v7：X5 开相机直取的三组对比实验

本入口直接调用相机SDK，取得图片后调用原有SDK DAG，不经过ROS图片话题，也不需要启动ROS相机节点。实现全部为C++，启动脚本是Bash，不需要专门Python环境。v6的录制回放入口仍保留。

## 1. 已配置的实验

| 方法 | 主配置 | 相机模式 | 算法消费的数据 | 功能 |
|---|---|---:|---|---|
| detseg_only | camera_detseg.json | 1 | 完整左NV12 | 检测、分割 |
| original | camera_original_q8.json | 2 | 完整左NV12、同帧原Q8 | 检测、分割、点云与原融合 |
| stereo | camera_stereo.json | 1 | 完整左NV12、同帧右NV12 | 检测、分割、新Stereo、点云与原融合 |

模式1请求关闭SDK内部连续视差生产；模式2请求生成原Q8。读取SDK模式进行确认，不支持时直接失败，不偷偷回退。模式1下真实相机SDK还必须能持续返回矫正后的左右图，需要板端验证。当前SDK取帧API会校验并复制左右图，detseg算法不消费右图，但不是零右图采集开销。

默认新模型仍为 `models/x5/r34_crop_stage2_i12_cheb5_max1_tail_int16_352x640_20261012.bin`，NV12底部crop，模型输入640×352。两个几何组统一ROI为 `(0,192,640,352)`；原Q8在计算计时内清除区域外的视差，新Stereo原位贴回、外部置0。检测分割始终使用完整640×544左图。

内参由每次开相机后的 `moGetCameraParams` 自动获取。仅接受已知640×544或1280×1088的矫正参考，必要时按既有规则缩放到640×544；不要求手填内参文件，不猜测未知参考几何。SDK报告的参数来源及缩放规则写入每组run.json。

## 2. 总配置与功能参数

根目录 `camera_benchmark.json`：

```json
{
  "schema_version": 1,
  "configurations": {
    "detseg_only": "camera_detseg.json",
    "original": "camera_original_q8.json",
    "stereo": "camera_stereo.json"
  },
  "order": ["detseg_only", "original", "stereo"],
  "frames": 1000,
  "warmup_frames": 10,
  "save_every_n": 0,
  "comparison_roi": {"x": 0, "y": 192, "width": 640, "height": 352},
  "bpu": {"enabled": true, "sample_interval_ms": 100, "paths": []}
}
```

这只是实验顺序、计量和输出配置，不是另一层DAG。每组流程仍由各自主配置的graph控制，功能参数仍从 `features/*/config.json` 加载。两种融合组主配置除了disparity_source外一致。

这三份配置应通过本说明的 `run_camera_benchmark.sh` / `run_camera_experiment.sh` 启动。原 `run_pipeline.sh` 仍是ROS应用入口，不能替代这个带统一ROI、暖机、定量采集和BPU统计的原生实验入口。

- `frames`：每组正式处理的唯一相机帧数；先用100快速检查，再用1000正式测量。
- `warmup_frames`：每组成功处理的暖机帧，不计入正式CPU/FPS/BPU窗口。
- `order`：三组串行顺序；可交换顺序再测一轮，检查温度/频率影响。
- `save_every_n=0`：不保存逐帧图片/PLY，保留指标和日志。需要看在线结果时改为50等正数，另用一个新输出目录运行；该轮含写盘成本，不作为纯性能基准。
- `bpu.paths=[]`：复用默认 `/sys/devices/system/bpu/bpu0/ratio`，它不是两核合计。需要另一接口时填入板上实际可读路径；缺失/不可解析保持null。
- `comparison_roi`：两组几何链路共同区域，必须匹配新模型crop。换模型尺寸时还需同步 `features/stereo/config.json` 的尺寸断言和ROI。

`camera.json` 配置SDK库和厂商参数文件。`camera_benchmark_visualization.json` 默认关闭逐帧保存、ROS发布，保留render_maps，使地图渲染成本与此前v6性能轮一致。SDK原debug/RGB着色参数继续继承；若测纯算法，请两组一起关相应渲染并另立结果目录。

## 3. 直接使用已编译X5运行包

将 `perception-stereo-cpp-v7.tar.gz` 放到X5并解压，例如：

```bash
cd /userdata
tar -xzf perception-stereo-cpp-v7.tar.gz
cd /userdata/perception-stereo-cpp-v7
export SDK_ROOT=$PWD/install/backend_sdk_x5
export INSTALL_ROOT=$PWD/install/perception_ros_so_demo_x5
export LD_LIBRARY_PATH=$SDK_ROOT/lib:/app/data/metoak/lib${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}
```

核对 `camera.json` 的两项路径。默认是：

```json
"sdk_library": "/app/data/metoak/lib/libMoGeneralSDK.so",
"vendor_config": "/app/data/metoak/demo/config/x5_camera.cfg"
```

测试时只允许本实验进程打开相机。先正常停止原有相机节点、ai_node或其他占用者，不同时启动 `run_camera_x5.sh`、ROS相机发布节点或另一个实验。

只检查配置和生成命令，不开相机、不加载模型：

```bash
bash tools/run_camera_benchmark.sh --prepare-only \
  --output /userdata/stereo_results/v7_camera_prepare_$(date +%Y%m%d_%H%M%S)
```

一条命令顺序跑完三组，默认每组10暖机＋1000正式帧：

```bash
bash tools/run_camera_benchmark.sh \
  --output /userdata/stereo_results/v7_camera_all_$(date +%Y%m%d_%H%M%S)
```

只跑其中一组：

```bash
bash tools/run_camera_experiment.sh --method detseg_only \
  --output /userdata/stereo_results/v7_camera_detseg_$(date +%Y%m%d_%H%M%S)

bash tools/run_camera_experiment.sh --method original \
  --output /userdata/stereo_results/v7_camera_q8_$(date +%Y%m%d_%H%M%S)

bash tools/run_camera_experiment.sh --method stereo \
  --output /userdata/stereo_results/v7_camera_stereo_$(date +%Y%m%d_%H%M%S)
```

输出目录必须全新；程序拒绝覆盖已有结果。Ctrl+C会转发给当前实验，结束后关闭相机、恢复原模式，保留partial，不启动下一组。厂商取帧若内部阻塞，取消和超时只能在其返回后生效；程序没有声称能抢占厂商调用。

## 4. 从源码交叉编译（此前Docker路径）

把源码解压到Ubuntu的 `/home/st/ini_code/perception-stereo-cpp-v7`，在Ubuntu主机：

```bash
cd /home/st/ini_code
docker start obs-v004-x5-build
docker cp perception-stereo-cpp-v7 obs-v004-x5-build:/tmp/
docker exec -it obs-v004-x5-build bash
```

容器内：

```bash
cd /tmp/perception-stereo-cpp-v7
export X5_SYSROOT=/work/obs_v004_x5/sysroot_docker
export X5_CXX_COMPILER=/usr/bin/aarch64-linux-gnu-g++
export STEREO_HORIZON_ROOT=$X5_SYSROOT/usr_x5
export TARGET_SYSTEM_PREFIX=$X5_SYSROOT/usr_x5
export BUILD_JOBS=2
# 仅修复历史sysroot解包造成的失效usr软链接。
if [[ -L "$X5_SYSROOT/usr" && ! -e "$X5_SYSROOT/usr" && -d "$X5_SYSROOT/usr_x5" ]]; then
  ln -sfnT usr_x5 "$X5_SYSROOT/usr"
fi
if [[ ! -e "$X5_SYSROOT/usr" && ! -L "$X5_SYSROOT/usr" && -d "$X5_SYSROOT/usr_x5" ]]; then
  ln -s usr_x5 "$X5_SYSROOT/usr"
fi
if [[ ! -e "$X5_SYSROOT/lib" && ! -L "$X5_SYSROOT/lib" ]]; then
  ln -s usr/lib "$X5_SYSROOT/lib"
fi
bash tools/build_x5_v7.sh
```

无需ROS underlay，输出SDK与原生实验程序到 `install/backend_sdk_x5` 和 `install/perception_ros_so_demo_x5`。退出容器后在Ubuntu复制：

```bash
docker cp obs-v004-x5-build:/tmp/perception-stereo-cpp-v7/install \
  /home/st/ini_code/perception-stereo-cpp-v7/
```

将整个工程传到X5。仅需要构建新增工具且已有匹配v6 SDK时，可设置 `PSDK_ROOT` 指向该SDK，设置同一X5_SYSROOT/STEREO_HORIZON_ROOT后执行 `bash tools/cross_build_compare.sh`，部署时保留匹配SDK。

## 5. 结果与指标

```text
输出目录/
├── index.html                      三组实时对比报告
├── report_zh.md / summary.json/csv  汇总
├── run_suite.json / executions.json / complete.json
├── configurations/各方法/          最终graph/参数/配置快照
├── detseg_only.log / original.log / stereo.log
└── detseg_only、original、stereo/
    ├── run.json                    相机模式、内参来源、ROI、模型契约
    ├── frames.jsonl                暖机标记、真实SDK帧身份、各阶段耗时
    ├── bpu_samples.jsonl / bpu_summary.json
    ├── complete.json               成功完成；中断为partial，错误为failed
    └── 可选逐帧结果                 图片/Q8/PLY，默认不生成
```

优先比较 `pipeline_fps/end_to_end_fps`：完整测量窗口的成功帧数/墙钟，包含相机等待、拷贝释放、算法、日志及配置的保存。`compute_fps`只反映算法计算窗口，不能当实际在线吞吐量。同步next→process不设置ROS传输或latest-frame队列；厂商内部缓存是否丢帧未知，保存真实ID/stamp和重复帧计数以便检查，不虚构传感器总帧率。

`window_cpu_percent`是同一测量窗口内整个进程CPU，100%=一核；包含相机SDK线程。`compute_cpu_percent`仍可能包含同期后台SDK工作，不能称纯模型CPU，也不要将采集CPU和计算CPU百分比相加。RSS与进程峰RSS分列，峰值包含初始化/暖机。

与此前录制回放不同，original组现在实际打开相机模式2，其本进程SDK线程的生产工作进入整窗CPU，设备BPU采样也覆盖在线工作。原视差内部独立计算耗时仍未知，`acquire_ms`包含等待/拷贝/释放等，不能直接叫原算法推理耗时。

**三组独立开相机，帧与时间不同，明确标为unpaired_live_runs。** 固定场景、曝光和相机位置有利于性能比较，但不能把第N帧当同帧计算视差差异。需要同数据精度比较，继续用v6的左右图＋Q8一次录制回放。

## 6. 验证范围

本轮主机配置、采集、控制器、信号和旧回放契约10/10通过，codec/NV12 2/2通过。使用真实ONNX＋相机ABI fixture验证了SDK内参缩放、唯一帧计量、同ROI Q8/PLY、缓存重复跳过、冻结超时、中断关闭和晚到中断不能写成功complete；这些不是实际硬件测试。

已交叉生成AArch64程序。未变的SDK后端复用v6已验证库，本轮改变的runner与控制器重新编译；用户完整构建脚本仍从源码构建SDK。没有连接X5真相机实测，不预填三组在线性能数值。
