# v6 三种输入六组推理测试

测试使用当前 v6 的 SDK 和输入适配器，每帧执行检测、分割和视差三个任务，不启用点云、地图、回充或 history。

| 输入 | original | crop |
| --- | --- | --- |
| camera | SDK 模式 2 取得左图和厂商生成的真实 Q8 | SDK 模式 1 取得左右图，运行新 crop Stereo 模型 |
| ros | 接收同采集时间戳的左图、Q8、CameraInfo | 接收同采集时间戳的左右图、CameraInfo，运行新模型 |
| offline | 读取矫正左图和对应的真实 Q8 文件 | 读取矫正左右图，运行新模型 |

`original` 在 DAG 内是校验、复制上游已经生成的 Q8。普通图片不能还原相机内部旧视差算法。ROS 和离线测试不会在消费者内重新执行厂商旧算法，因此旧视差导入节点耗时不能与新模型推理耗时直接等同。

三种输入统一使用 `demo`：camera 从 SDK 直接采集，offline 读文件，只有 ros 使用输入话题；三个入口的程序都链接 ROS 运行库。独立原生相机程序可另行使用，不是六组统一入口。

## 代码入口

项目根目录下：

```text
config/inference_matrix/                 六组主配置和共享功能配置
tools/configure_inference_matrix.py      按实际数据生成配置
tools/build_inference_matrix_in_container.sh  Ubuntu 宿主机 Docker 编译与打包
tools/build_inference_matrix_x5.sh       编当前 ARM SDK 和 ROS 程序
tools/run_inference_matrix.sh            一次运行一组并检查结果
tools/run_inference_matrix_publisher.sh  ROS 组的可选相机发布者
tools/check_inference_matrix_run.py      核对完成帧、任务状态及保存文件
tools/summarize_inference_matrix.py      汇总完成帧的耗时和资源指标
```

默认模型为项目中的 `mmyolo0828.bin`、`pidnet_0825_3classes.bin` 和 `r34_crop_stage2_i12_cheb5_max1_tail_int16_352x640_20261012.bin`。新视差固定 `image_transform=crop`、输入 640×352：640×544 原图保留底部 `(0,192,640,352)`，推理 Q8 贴回原图坐标，顶部未计算区域为无效值 0。

## 编译

### Ubuntu 宿主机使用已有 Docker 容器

在 Ubuntu 宿主机解压当前项目后执行以下命令。脚本复用 `obs-v004-x5-build`，先预检容器中的 AArch64 ROS、Eigen 和交叉编译环境，再直接调用当前六组测试的构建入口，最后取回运行包。

```bash
cd /home/st/ini_code/perception-stereo-cpp-v8-dag-v6-algorithm-plugins
bash tools/build_inference_matrix_in_container.sh \
  --container obs-v004-x5-build \
  --sysroot /work/obs_v004_x5/sysroot_docker \
  --dependency-prefix /work/obs_v004_x5/sysroot_docker/usr_x5 \
  --stereo-horizon-root /work/obs_v004_x5/sysroot_docker/usr_x5 \
  --target-ros-prefix auto \
  --eigen-dir auto \
  --jobs 2 \
  --out "/home/st/ini_code/v6_matrix_build_$(date +%Y%m%d_%H%M%S)_$$"
```

`--out` 必须是新的宿主机输出目录。当前用户需有 Docker 权限；其余开发依赖路径均指容器内路径，不是 Ubuntu 宿主机路径。

| 参数 | 默认值或填写方法 |
| --- | --- |
| `--container` | `obs-v004-x5-build`，已有 X5 开发容器 |
| `--sysroot` | `/work/obs_v004_x5/sysroot_docker` |
| `--dependency-prefix` | 默认使用所选 sysroot 的 `usr_x5`；依赖在别处时填实际 ARM 前缀 |
| `--stereo-horizon-root` | 默认使用依赖前缀；Horizon 单独部署时填其容器内路径 |
| `--target-ros-prefix` | `auto` 自动查找；也可显式指定 AArch64 ROS 前缀，多个前缀用分号并整体加引号 |
| `--eigen-dir` | `auto` 自动查找；也可指定含 `Eigen3Config.cmake` 的目录 |
| `--jobs` | 并行编译数，示例为 2 |
| `--out` | 新的 Ubuntu 宿主机输出目录 |

ROS 前缀必须含目标架构的开发包，包括 `nav_msgs`。自动预检发现缺失或架构不匹配时会停止，应按诊断补齐或指定正确路径；不能把 x86 ROS 库用于 ARM 链接。

若之前运行 `tools/build_in_container.sh` 报 `Missing Ubuntu host tool: build/benchmark6/r36_benchmark6`，原因是该历史入口调用旧的业务与 benchmark6 打包链，需要额外的 Ubuntu 主机工具。当前六组输入推理测试使用上面的专用入口，**无需先运行 `--host-only`**，也不要求旧 benchmark6 主机二进制。

成功后输出目录包含：

```text
perception-v6-matrix-x5.tar.gz
perception-v6-matrix-x5.tar.gz.sha256
build.log
environment.txt
```

运行包包含当前项目源码、模型、配置、工具及 `install/backend_sdk_x5`、`install/perception_ros_so_demo_x5` 两个新编译的 ARM 安装目录。包内顶层目录为 `perception-stereo-cpp-v8-dag-v6-algorithm-plugins`；相机和平台系统库使用 X5 已安装版本，不随包复制。

在 Ubuntu 宿主机将包发送到 X5：

```bash
OUT=/home/st/ini_code/实际输出目录
cd "$OUT"
sha256sum -c perception-v6-matrix-x5.tar.gz.sha256
adb push perception-v6-matrix-x5.tar.gz /userdata/
adb shell
```

进入 X5 shell 后解压到新目录：

```bash
DEPLOY=/userdata/v6_matrix_$(date +%Y%m%d_%H%M%S)_$$
mkdir "$DEPLOY"
tar -xzf /userdata/perception-v6-matrix-x5.tar.gz -C "$DEPLOY"
cd "$DEPLOY/perception-stereo-cpp-v8-dag-v6-algorithm-plugins"
```

然后执行下方板端环境与 `ldd` 检查，再生成实际数据配置、逐组运行。交叉编译成功不能替代板端动态库检查和相机测试。

### 已有开发环境直接编译

已经进入具备完整开发依赖的 Ubuntu 主机或容器时，也可直接编译。需要匹配 X5 的 AArch64 编译器、Horizon、OpenCV 和现有构建脚本要求的开发库；ROS 开发前缀必须也是 AArch64，包含 nav_msgs。

```bash
cd /实际路径/perception-stereo-cpp-v8-dag-v6-algorithm-plugins
export X5_SYSROOT=/实际路径/X5_sysroot
export TARGET_SYSTEM_PREFIX="$X5_SYSROOT/usr_x5"
export STEREO_HORIZON_ROOT="$TARGET_SYSTEM_PREFIX"
export TARGET_ROS_PREFIX=/实际路径/AArch64_ROS/humble
export BUILD_JOBS=2
bash tools/build_inference_matrix_x5.sh
```

只有依赖确实位于 `usr_x5` 时才采用上述前缀；位于 `usr` 时改为实际目录。安装结果是 `install/backend_sdk_x5` 和 `install/perception_ros_so_demo_x5`。部署时将当前源码、配置、模型和这两个安装目录保持相同布局复制到 X5；板端相机与平台库继续使用该板已安装版本。

### X5 运行环境检查

在 X5 的每个运行终端中执行。Docker 包解压后可在上面的项目目录继续；手动部署时先进入实际项目目录：

```bash
export ROS_SETUP=/opt/ros/humble/setup.bash
source "$ROS_SETUP"
source tools/x5_runtime_env.sh
ldd "$SDK_ROOT/lib/libperception_sdk.so"
ldd "$INSTALL_ROOT/lib/perception_ros_so_demo/demo"
ldd /app/data/metoak/lib/libMoGeneralSDK.so
```

将 ROS_SETUP 改成板端真实 ROS/TROS setup.bash。依赖不应有 `not found`。相机 SDK 默认 `/app/data/metoak/lib/libMoGeneralSDK.so`，厂商配置默认 `/app/data/metoak/demo/config/x5_camera.cfg`，不同环境可在生成配置时使用 `--camera-sdk`、`--camera-config` 覆盖。

运行脚本还需要 Python 3、GNU timeout、Bash 和 tee。Python 负责生成配置与检查文件，实际模型执行仍由 C++ SDK 完成。

## 准备离线数据

数据应来自同一次采集，左右图已经矫正，尺寸均为 640×544，内参与该尺寸一致。按相同文件主名配对，例如：

```text
/userdata/v6_data/
  left/frame000001.png
  left/frame000002.png
  right/frame000001.png
  right/frame000002.png
  q8/frame000001.u16
  q8/frame000001.u16.json
  q8/frame000002.u16
  q8/frame000002.u16.json
  intrinsics.json
```

Q8 支持真实 16-bit 单通道 PNG，或紧凑 little-endian uint16 `.raw/.q8/.u16`。raw 文件不含行 padding，文件大小必须为 `640*544*2=696320` 字节，旁边的 `<完整文件名>.json` 必须为：

```json
{
  "width": 640,
  "height": 544,
  "encoding": "16UC1",
  "byte_order": "little",
  "value_format": "q8.8"
}
```

PNG 也必须由原视差数据导出，不能使用 8 位可视化图或以毫米为单位的深度图。Q8 数值除以 256 才是像素视差。全 0 可表示一帧全部无效，不会伪造有效视差。

`intrinsics.json` 参考项目 `calibration/intrinsics.example.json`，填写真实 `width/height/fx/fy/cx/cy/bxf`；`bxf=焦距像素×基线毫米`。模板中的 null 不能用于运行。

在 X5 上生成实际配置，目录必须是新的：

```bash
python3 tools/configure_inference_matrix.py \
  --output "$PWD/results/matrix_configs_001" \
  --left-dir /userdata/v6_data/left \
  --right-dir /userdata/v6_data/right \
  --q8-dir /userdata/v6_data/q8 \
  --intrinsics /userdata/v6_data/intrinsics.json \
  --rectified --fps 2 --save-every 10
export MATRIX_CONFIG_DIR="$PWD/results/matrix_configs_001"
```

生成器把离线数据写成该主机的绝对路径，故应在 X5 数据部署完成后生成。`--rectified` 表示调用者确认输入已经正确矫正，不执行图像矫正。左右图和 Q8 目录文件主名必须完全一致，避免按排序误配。

仅测 camera/ROS 时，可以直接使用随包 `config/inference_matrix`，或不传数据参数生成新的配置目录。随包离线列表为空，必须提供真实数据再运行离线组。

## 六组运行命令

以下均在 X5 当前项目根目录执行，逐组运行，不要让多个进程同时打开同一相机。运行目录必须未存在。在线组默认 30 秒、至少 10 个成功帧；离线组还要求在时限内把全部配置文件处理且只处理一次。

先对所需组执行配置准备，可将任意下面的运行命令加上 `--prepare-only`，并使用单独的新运行目录。

### camera 直取

```bash
bash tools/run_inference_matrix.sh --source camera --method original \
  --config-dir "$MATRIX_CONFIG_DIR" --run-dir /userdata/v6_runs/camera_original_001 --duration 30

bash tools/run_inference_matrix.sh --source camera --method crop \
  --config-dir "$MATRIX_CONFIG_DIR" --run-dir /userdata/v6_runs/camera_crop_001 --duration 30
```

### ROS 输入

原视差组，终端 A 启动发布者：

```bash
bash tools/run_inference_matrix_publisher.sh original "$MATRIX_CONFIG_DIR"
```

终端 B 运行消费者：

```bash
bash tools/run_inference_matrix.sh --source ros --method original \
  --config-dir "$MATRIX_CONFIG_DIR" --run-dir /userdata/v6_runs/ros_original_001 --duration 30
```

消费者完成后，在终端 A Ctrl+C 退出原发布者，再启动 crop 发布者：

```bash
bash tools/run_inference_matrix_publisher.sh crop "$MATRIX_CONFIG_DIR"
```

终端 B 运行：

```bash
bash tools/run_inference_matrix.sh --source ros --method crop \
  --config-dir "$MATRIX_CONFIG_DIR" --run-dir /userdata/v6_runs/ros_crop_001 --duration 30
```

也可以使用自己的发布者，修改生成目录中的 `ros.json`。原视差需要 left/Q8 和 CameraInfo；crop 需要 left/right 和 CameraInfo。每次采集的数据必须使用完全一致的采集时间戳，QoS 需兼容。内置发布者 original 使用 map/SDK 模式 2，crop 使用 infer/SDK 模式 1。

### 离线图片

```bash
bash tools/run_inference_matrix.sh --source offline --method original \
  --config-dir "$MATRIX_CONFIG_DIR" --run-dir /userdata/v6_runs/offline_original_001 --duration 120

bash tools/run_inference_matrix.sh --source offline --method crop \
  --config-dir "$MATRIX_CONFIG_DIR" --run-dir /userdata/v6_runs/offline_crop_001 --duration 120
```

时限至少覆盖 `图像数量/fps + 模型初始化和处理余量`，不够时检查器会报告预计和实际帧数并返回失败。离线输入用当前回放时间戳关联文件，不冒充原始采集时间。默认 2 FPS 是输入供给速率，不是模型峰值吞吐。

## 结果检查与指标

每个运行目录包含 requested/normalized/resolved 配置、`effective_full.json`、`parameters.yaml`、`metrics.jsonl`、`console.log` 和 `runner_status.json`。

检查器要求三个任务在每个完成帧均 succeeded，拒绝提前退出、零帧、日志中的运行错误、离线未处理完整和应保存而缺失的结果。`runner_status.json.passed=true` 表示本次运行及这些产物检查通过，不表示业务准确率已通过。

默认每 10 帧保存一次，保存目录见 `resolved.json.parameters.save_root`，通常为项目 `results/inference_matrix_frames/<运行目录名>/frame-<id>-<stamp>/`。确定产物包括检测框所在的 `result.json`、分割 `mask.bin`、数值视差 `disparity_q8.u16`、`disparity.png`、任务轨迹和完整标记。`disparity.png` 仅可视化；数值比较使用 `.u16`。纯推理图不保证产生 RGB/叠加图。

汇总六组完成帧，默认排除每组前 10 个指标行：

```bash
python3 tools/summarize_inference_matrix.py \
  /userdata/v6_runs/camera_original_001 /userdata/v6_runs/camera_crop_001 \
  /userdata/v6_runs/ros_original_001 /userdata/v6_runs/ros_crop_001 \
  /userdata/v6_runs/offline_original_001 /userdata/v6_runs/offline_crop_001 \
  --warmup 10 --output /userdata/v6_runs/summary_001.json
```

少于 10 帧时可显式使用 `--warmup 0`。汇总包含检测/分割各阶段、整体计算、视差、队列、保存耗时、CPU 和 RSS 的 mean/p50/p95，缺失值保留 null；该 ROS 指标流不测 BPU 利用率。累计 FPS 字段包含输入等待，保存会影响整体速度。

camera 的进程 CPU 包含其 SDK 线程；ROS 消费者不包含独立相机发布进程。两次在线采集也不是相同场景帧，不能用六组独立运行结果直接得出同帧精度结论。

需要纯原生相机 CPU/RSS/BPU 实验时，当前 `r36_camera_compare/r36_compare_runner` 可用，见 `tools/run_camera_experiment.sh`；使用这里的 camera 主配置可保持仅 det/seg/disparity，必须区分采样与计算口径。
