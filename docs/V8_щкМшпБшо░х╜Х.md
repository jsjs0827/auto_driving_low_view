## 4. 运行边界与结果解读

- 输出目录必须不存在。输入解析、文件大小、相机模式与配置检查在打开设备/模型之前完成；实际创建目录仍由 `prepare` 的独占新目录检查把关。
- 检查配置与生成配置之间若发生变化，入口拒绝启动，避免用一份时间线跑另一份图或标定。
- 录制路径相对 `timeline.csv`，功能配置路径相对主 JSON，录制内参必须显式指定。相机内参来自相机 SDK，接受已核实的 640×544 或 1280×1088 参考几何。
- 一个运行固定一个采集 epoch、模型、ROI 与标定；跨这些边界使用新的运行和新的 SDK 实例。时间倒退不会通过改写时间来隐藏。
- 轮速与图像必须处于明确确认的同一时钟域；参考应为测得的轮速/编码器运动，不是控制指令速度。缺少插值端点、内部参考断档、视觉质量不足、转弯过大、低速或外参未确认时，可得到不可判断结果。
- 第一帧没有前一帧运动区间，运动区间结束时间可以为 0；顶层 `timestamp_ns` 仍是该帧的真实采集时间。
- `complete.json` 表示输入处理成功完成，不表示存在有效打滑判断。查看 `visual_valid_frames`、`reference_valid_frames`、`evaluated_frames` 与逐帧原因；没有有效判断时不应将缺失数据解释为“正常”。
- CPU 时间包括当前进程的所有线程，100% 对应一个逻辑核。全循环 FPS 包含采集/读盘、运动参考推送、处理和输出；逐帧 `total_ms` 的截止点在本行 metrics 与 stdout 写出之前。初始化/模型加载与设备关闭不属于全循环指标。
- BPU 是设备共享的采样值，不能按模型或进程归因；驱动统计窗没有被重置。原相机 SDK 内部视差生成耗时仍为 `null`，相机模式 2 的生产线程成本包含在整进程测量中。
- 正常采集与处理期间的 SIGINT/SIGTERM 使用受控退出并生成 `partial.json`；关闭后和提交结果前会再检查中断。此次 Windows 集成没有验证真实相机的信号关闭路径。

本记录尚未验证真实相机、真实新 Stereo BPU 推理、真实轮速时钟标定或物理打滑真值。新 Stereo 的调用接线保留真实 `StereoProvider`，不支持 Horizon 的构建会明确拒绝该模式，不会回退成旧视差或构造推理结果。

`--check` 也不查询 BIN 的实际张量元信息；真实模型输入类型、形状与输出合同由支持 Horizon 的运行时初始化继续检查。
