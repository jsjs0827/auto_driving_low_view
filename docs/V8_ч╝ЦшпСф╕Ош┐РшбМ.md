# V8 编译、部署与运行

以下指令使用此前 Ubuntu `/home/st/ini_code`、Docker `obs-v004-x5-build`、容器 sysroot `/work/obs_v004_x5/sysroot_docker` 和板端 `/userdata` 路径。先使用原 Q8 验证视觉运动，再按同一份录制数据切换新 Stereo。

## 1. Docker 启动与 Ubuntu 交叉编译

将本次 v8 源码包解压到 Ubuntu `/home/st/ini_code/perception-stereo-cpp-v8`。在 **Ubuntu 主机**执行：

```bash
cd /home/st/ini_code/perception-stereo-cpp-v8
docker start obs-v004-x5-build
bash tools/build_in_container.sh \
  --container obs-v004-x5-build \
  --sysroot /work/obs_v004_x5/sysroot_docker \
  --out /home/st/ini_code/perception_stereo_cpp_v8_release_$(date +%Y%m%d_%H%M%S)
```

脚本将源码复制到容器的新临时目录，编译本次 SDK 和原生工具，再生成含安装产物的 `perception-stereo-cpp-v8.tar.gz` 及 SHA256。不要传旧版本 `--sdk-root`；新 API 需要本次 v8 SDK。容器必须已经存在，并具备原来的 AArch64 编译器、Horizon、OpenCV、PCL、Eigen 等目标依赖。

需要手动检查编译过程时，在 Ubuntu 主机执行：

```bash
cd /home/st/ini_code
docker cp perception-stereo-cpp-v8 obs-v004-x5-build:/tmp/
docker exec -it obs-v004-x5-build bash
```

在 **容器内**执行：

```bash
cd /tmp/perception-stereo-cpp-v8
export X5_SYSROOT=/work/obs_v004_x5/sysroot_docker
export X5_CXX_COMPILER=/usr/bin/aarch64-linux-gnu-g++
export STEREO_HORIZON_ROOT=$X5_SYSROOT/usr_x5
export TARGET_SYSTEM_PREFIX=$X5_SYSROOT/usr_x5
export BUILD_JOBS=2

# 仅适用于此前sysroot解包留下的失效usr软链接；已有正常usr不改动。
if [[ -L "$X5_SYSROOT/usr" && ! -e "$X5_SYSROOT/usr" && -d "$X5_SYSROOT/usr_x5" ]]; then
  ln -sfnT usr_x5 "$X5_SYSROOT/usr"
fi
if [[ ! -e "$X5_SYSROOT/usr" && ! -L "$X5_SYSROOT/usr" && -d "$X5_SYSROOT/usr_x5" ]]; then
  ln -s usr_x5 "$X5_SYSROOT/usr"
fi
if [[ ! -e "$X5_SYSROOT/lib" && ! -L "$X5_SYSROOT/lib" ]]; then
  ln -s usr/lib "$X5_SYSROOT/lib"
fi
bash tools/build_x5_v8.sh
bash tools/package_release.sh /tmp/perception_stereo_cpp_v8_release
```

主机取回手动编译的包：

```bash
docker cp obs-v004-x5-build:/tmp/perception_stereo_cpp_v8_release/. \
  /home/st/ini_code/perception_stereo_cpp_v8_release/
```

安装产物为：

```text
install/backend_sdk_x5/                       本次完整SDK与配置模板
install/perception_ros_so_demo_x5/
  bin/perception_config                      配置准备工具
  lib/perception_ros_so_demo/r36_slip_runner   多帧运动入口
  bin/r36_stereo_capture
  share/perception_ros_so_demo/               配置/模型安装副本
```

如需交叉编译 ROS 应用，额外设置实际 **AArch64** `TARGET_ROS_PREFIX`，执行 `bash tools/build_x5_v8.sh --with-ros`。主机的 x86 `/opt/ros/humble` 不能充当板端依赖。新增 ROS 参考需要目标 `nav_msgs` 包；原生相机/录制入口不需要 ROS。

## 2. X5 相机直取

将编译后的 `perception-stereo-cpp-v8.tar.gz` 和其 `.sha256` 传到 X5。**源码包与已编译运行包要区分**：源码包不含 `install/backend_sdk_x5` 时，需先完成上一节交叉编译。

```bash
cd /userdata
sha256sum -c perception-stereo-cpp-v8.tar.gz.sha256
tar -xzf perception-stereo-cpp-v8.tar.gz
cd /userdata/perception-stereo-cpp-v8
export SDK_ROOT=$PWD/install/backend_sdk_x5
export INSTALL_ROOT=$PWD/install/perception_ros_so_demo_x5
export CAMERA_SDK_ROOT=/app/data/metoak/lib
export LD_LIBRARY_PATH=$SDK_ROOT/lib:$CAMERA_SDK_ROOT${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}

# 不打开相机，只检查配置。output需要是不存在的新目录。
bash tools/run_slip.sh --config "$PWD/slip_camera.json" \
  --output /userdata/slip_results/check_$(date +%Y%m%d_%H%M%S) --check

# 开相机处理，默认100个唯一采集帧。
bash tools/run_slip.sh --config "$PWD/slip_camera.json" \
  --output /userdata/slip_results/camera_$(date +%Y%m%d_%H%M%S)
```

根 `camera.json` 默认 SDK 为 `/app/data/metoak/lib/libMoGeneralSDK.so`，厂商参数为 `/app/data/metoak/demo/config/x5_camera.cfg`。相机内参自动读取；不填写离线内参。`slip_camera.json` 的 `runtime.max_frames:0` 表示持续运行，Ctrl+C 正常关闭并写部分汇总。运行期间先正常停止其他相机占用进程。

默认 `features/motion_reference/config.json` 没有参考源，外参 `confirmed:false`。这时可以先观察视觉位移、匹配、质量和不可用原因。相机原生入口当前只提供轮速 CSV 适配器；持续在线轮速可通过 SDK 新 API 接入自有采集应用，或选择下一节 ROS Odometry 入口。不要把历史轮速文件或控制命令冒充本次测量轮速。

## 3. 录制与相同数据回放

录制器使用原来的原生入口，相机需由此进程独占：

```bash
"$INSTALL_ROOT/bin/r36_stereo_capture" \
  --sdk /app/data/metoak/lib/libMoGeneralSDK.so \
  --camera-config /app/data/metoak/demo/config/x5_camera.cfg \
  --output /userdata/recorded_motion \
  --frames 1000 --timeout-ms 3000
```

本版本同时生成原 `manifest.jsonl` 和新 `timeline.csv`，时间、身份及三路文件来自同一次采集。输出目录必须全新。轮速必须另行录制成同钟 `timestamp_ns,linear_speed_mps,yaw_rate_radps` CSV。

准备好数据后：

```bash
export CAPTURE_ROOT=/userdata/recorded_motion
bash tools/run_slip.sh --config "$PWD/slip_recording.json" \
  --output /userdata/slip_results/q8_$(date +%Y%m%d_%H%M%S)
```

`slip_recording.json` 使用 `${CAPTURE_ROOT}/timeline.csv` 和 `${CAPTURE_ROOT}/metadata.json`。也可直接写实际文件的相对路径。`recording.limit:0` 表示全部时间线；多帧运动要求 `warmup_frames:0,repeat:1`，不能靠重复播放拼接新时间。回放不按采集 FPS 节流，但所有位移/速度/滞回仍使用原时间戳。

相同数据测试新模型：复制根 `slip_recording.json` 为 `slip_recording_stereo.json`，仅将 `input.disparity_source` 改为 `raft_stereo`；保证 timeline 含同帧 `right_nv12`，然后运行到新目录：

```bash
bash tools/run_slip.sh --config "$PWD/slip_recording_stereo.json" \
  --output /userdata/slip_results/stereo_$(date +%Y%m%d_%H%M%S)
```

模型仍由 `features/stereo/config.json` 的相对 `model` 路径管理，使用已有底部 NV12 crop 和恢复完整 Q8 的实现。保持同一视觉 ROI、外参、轮速、时间线与阈值，才适合比较原 Q8 和新 Stereo。单帧图片序列没有可靠原时间戳时只能做单帧功能测试，不能据此计算物理速度。

## 4. ROS 图像与轮速

在已经编译安装 v8 ROS 应用和其依赖的 X5：

```bash
cd /userdata/perception-stereo-cpp-v8
export SDK_ROOT=$PWD/install/backend_sdk_x5
export INSTALL_ROOT=$PWD/install/perception_ros_so_demo_x5
export ROS_SETUP=/app/humble/setup.bash
bash tools/run_pipeline.sh --config "$PWD/slip_ros.json" \
  --run-dir /userdata/slip_results/ros_$(date +%Y%m%d_%H%M%S)
```

在 `features/motion_reference/config.json` 设置 `odom_topic:"/wheel/odom"`、可靠的 `clock_domain`、`same_clock_confirmed:true`，并保持 `input_csv:null`。Odometry 的 `child_frame_id` 必须等于配置的 `robot_frame_id`（默认 `base_link`）；读取 `twist.twist.linear.x` 和 `angular.z`。图像、Q8、左右 CameraInfo 的时间配对延续原逻辑。

新增 `wait_timeout_ms` 默认50，范围0～2000。算法 worker 最多等待该时长，直到已收到覆盖本帧采集时间的测量轮速；ROS 回调继续收消息。超时继续处理图像，缺边界就输出不可用，不外推。它增加在线延迟，不能修复不同的时钟或丢失的测量。源时钟重置后重启会话。

```bash
ros2 topic echo /perception_ros_so_demo/slip
ros2 topic info /wheel/odom --verbose
```

`~/slip` 是 `std_msgs/msg/String` 的 JSON。原 `~/result`、`~/history`、`~/metrics` 保留。

## 5. Windows 本机调试

在本项目根目录 PowerShell 执行：

```powershell
.\tools\generate_vs2022.ps1 -Build
ctest --test-dir build/vs2022 -C Debug -R "v8_|slip_timeline" --output-on-failure
```

解决方案为 `build/vs2022/perception_stereo_cpp_v8.sln`。保留原 `perception_windows_debug` 的 CPU ONNX 单帧入口，新增 `r36_slip_runner` 可以调试原 Q8 多帧录制、DAG 和打滑状态；Windows 不支持本项目的 Linux 相机 SDK/BPU入口。

用 C++ 测试工具生成一份独立合成数据，再调试实际 runner：

```powershell
$env:SDK_ROOT = (Resolve-Path build/vs2022/sdk).Path
$demoPath = Join-Path $PWD ('output/slip_demo_' + (Get-Date -Format yyyyMMdd_HHmmss))
$resultPath = $demoPath + '_result'
.\build\vs2022\sdk\shared\Debug\slip_sdk_contract_test.exe --generate-demo $demoPath $PWD
.\build\vs2022\features\slip_app\Debug\r36_slip_runner.exe --config "$demoPath/pipeline.json" --output $resultPath
```

生成器显式使用本地测试 SDK 配置，不要求 AI 模型或相机。数据是固定纹理、固定正视差、模拟轮速，预期初始化→待确认→打滑，只验证代码接线和状态。真实采集数据必须换成实测内参/外参与同步轮速。F5 时选择 `r36_slip_runner`，调试参数设置为同样的 `--config ... --output ...`，每次更换输出目录。

## 6. 结果与数据有效性

`--output` 下读取 `slip.jsonl`、`metrics.jsonl`、`bpu_samples.jsonl`、实际生效配置和 `complete.json`。汇总分别记录处理帧、视觉有效、参考有效、可比较及打滑帧数。`complete` 仅表示遍历/处理正常结束，不表示每帧都具备打滑判定条件。

SDK C ABI 的无效速度/打滑率为 NaN；JSON 为 `null`，结合 `state`、`visual_valid`、`reference_valid`、`reason` 使用。BPU是设备共享采样，读不到时为 `null`。CPU100%对应一个逻辑核；Debug 和合成数据耗时不能当作 X5 性能。
